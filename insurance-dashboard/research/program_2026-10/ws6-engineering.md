# ws6 — Engineering review (web/ + pipeline/), 22 Oct 2026

Method: read `web/src` (9,306 lines), `vite.config.ts`, `firebase.json`, `deploy.sh`, `package.json`, pipeline docstrings and `EXTRACT_SPEC.md`; measured the live site with `curl` (raw/gzip/brotli per asset) and a headless-Chrome net-log capture of 10 routes (script `scratchpad/ws6_net.sh`, parsed by `ws6_netparse.py`, raw logs in `scratchpad/ws6_net/`). Nothing under the repo was edited. Tags: [V] verified by me, [T] second-hand, [J] judgment.

## 1. Verdict

Engineering today: **5/10**. The codebase is small, strict-TypeScript, consistently written, and the data pipeline has a provenance discipline most paid tools lack; but the delivery layer is a prototype: HashRouter with no clean URLs or share previews, one 499 KB JS chunk for 27 pages, a 426 KB (brotli; 1.83 MB raw) `market.json` fetched on every route because the search box in the layout asks for it, no tests, no CI, no error boundary, no observability, no auth/sync, three unrelated search implementations, and a build that only works through a shell workaround because the repo lives in Google Drive. Measured first-route transfer is 780–990 KB compressed on every page, of which the shell (JS+CSS) is 331 KB and `market.json` 43–55 %. Best competitor on engineering: Koyfin ≈ 8/10 [T] (clean shareable URLs, account sync, per-route loading; not measured by me). The gap is closable in one quarter without touching a single data asset, and the data assets are the moat.

**W6-1 — `market.json` (426 KB br / 1.83 MB raw) ships on every route; A3-D1 still open, root cause is the search box.** Evidence: table above; `web/src/components/Search.tsx:22` calls `useMarketData()` unconditionally (the `enabled` flag only gates `search/rows.json` on line 24); `Search` is mounted in `Layout.tsx:50`, so `Company.tsx:37`'s careful gating is bypassed. `Source.tsx:90` (`FundSheet`) also calls `useMarket()` ungated but only mounts inside the sheet. Why: on a phone over 4G this is the difference between a 1 s and a 3–4 s first paint on the statements page, and it is the single largest line in every route. Fix: pipeline emits `search/entities.json` (companies + 16 groups + 1,251 fund names ≈ 60 KB raw / ~12 KB br); `useIndex` loads it instead of `market.json`; pass `enabled` to `useMarketData`. **S**.

**W6-2 — No route-level code splitting: 27 pages + all libs in one chunk, charts chunk preloaded even on pages without charts.** Evidence: `App.tsx:3-22` static imports; `vite.config.ts` only splits `echarts` and the framework; live `index.html` `<link rel="modulepreload">` for `charts-*.js` (152 KB br) on `/company/x/filings`, `/industry/search`, `/companies` which draw no chart; `labels.ts` (37 KB), `csm.ts` (22 KB), `kpi.ts` (21 KB), `market.ts` (17 KB) parsed on every route. Why: 331 KB of JS before first paint; every release invalidates everything. Fix: `React.lazy` per route group (company / industry / funds / valuation / home), `Chart.tsx` behind `lazy()` so ECharts loads on first chart, data-shaped constants (`METRIC_HE`) moved to a JSON the pipeline writes. Expected shell ≈ 60 KB br on text routes. **S–M**.

**W6-3 — HashRouter: no clean URLs, no server rewrites, no share previews.** Evidence: `main.tsx:11` `HashRouter`; `firebase.json` has no `rewrites`; `curl https://fox-research-il.web.app/company/harel` → `404`, 21,376-byte Firebase default page [V]; `index.html` has `<title>fox</title>`, no `description`, no Open Graph / Twitter tags, so a link pasted into WhatsApp, Slack or email previews as "fox" with nothing [V]. Why: analysts share links; a `#/` URL with no preview reads as a hobby site, and `X-Robots-Tag: noindex` plus hash routing means the product cannot be found or cited. Fix: `BrowserRouter` + `rewrites: [{ "source": "**", "destination": "/index.html" }]`; a 10-line boot shim that rewrites legacy `/#/x` to `/x` (`history.replaceState`); per-route OG tags via (a) build-time prerendered HTML stubs for the ~60 canonical routes (company × tab, industry tabs) or (b) one Cloud Function `share` that returns an OG-only HTML for bots and 302s humans. Keep `noindex` only while the owner wants it private. **M**.

**W6-4 — No CI, no tests of any kind, deploy gates are a file count.** Evidence: git repo exists one level up (`ohad/.git`, remote `github.com/ohadbarr1/ohad.git`, branch `claude/festive-ramanujan-7f9ihj`, 2,584 tracked files including the 1,656 data JSON) but no `.github/`; `web/` has no eslint/vitest/playwright config (eslint-disable comments exist without an eslint config); `package.json` has no `test` script; `deploy.sh:10` runs `tsc` and line 17 checks `have ≥ want` file count only; `pipeline/check_workbook.py` docstring says "run before a deploy" but nothing runs it; `verify_prov.py` ("Gate: every regulator aggregate…") is likewise manual. Why: audit 3 found ×1000 per-share errors and duplicate rows that a data-contract test would have caught before deploy; every refactor proposed in this report is unsafe without a net. Fix: GitHub Actions on push/PR: `tsc` → `check_workbook.py` + `verify_prov.py` + JSON schema validation → `vite build` → Playwright smoke (10 routes × 390/1440 × 2 themes, screenshot diff) → `firebase hosting:channel:deploy pr-<n>` on PR, live on `main`. **M**.

**W6-5 — Repo on Google Drive: builds stall, `deploy.sh` is a workaround, git is at risk.** Evidence: `deploy.sh:2-4,13` ("reads from the synced folder can take seconds each… copied in parallel… `xargs -0 -P 32`"); `RESUME.md:137-139` ("vite build regular gets stuck on copying public/ (1,650 files)… killed a stuck build"); my own `wc`/`grep` over `pipeline/` took > 120 s. Drive also rewrites mtimes and creates "(1)" conflict copies inside `.git` on sync races [T]. Why: a 10-minute build/deploy loop kills iteration speed and makes CI the only sane build host. Fix: clone to `~/code/ohad` (local SSD), keep Drive for documents/PDFs only (symlink `data/sources`), CI builds from GitHub, `deploy.sh` becomes `git push`. **S** (one afternoon), low risk.

**W6-6 — No error boundary, no global error capture: any render exception is a white page.** Evidence: grep for `ErrorBoundary|componentDidCatch|onerror|unhandledrejection` in `web/src` → none; `useLoad` (`useData.ts:19-29`) handles fetch errors only. Why: one malformed JSON row after a pipeline run blanks the whole app for the user with no signal to the owner. Fix: `RouteErrorBoundary` around `<Outlet/>` in `Layout.tsx:54` with "reload / report" UI; `window.onerror` + `unhandledrejection` → Sentry free tier (or a Cloud Function log sink). **S**.

**W6-7 — Security headers: only HSTS (Firebase default) and `X-Robots-Tag`.** Evidence: `curl -sI /` [V]: no `Content-Security-Policy`, `X-Content-Type-Options`, `X-Frame-Options`/`frame-ancestors`, `Referrer-Policy`, `Permissions-Policy`. The inline theme script in `index.html:6-8` blocks a strict CSP. Why: low exploit surface (static site) but clickjacking/framing is trivial and enterprise buyers scan for this. Fix: `firebase.json` headers: `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy: camera=(), microphone=(), geolocation=()`, `Content-Security-Policy: default-src 'self'; script-src 'self' 'sha256-<theme-script>'; style-src 'self' 'unsafe-inline'; font-src 'self'; img-src 'self' data:; connect-src 'self'; frame-ancestors 'none'` (after self-hosting fonts, W6-20). **S**.

**W6-8 — Data caching is time-based (300 s), not content-addressed; no service worker, no offline, no web manifest.** Evidence: `firebase.json` `data/** max-age=300`; data paths carry no hash; `index.html` has `apple-mobile-web-app-*` meta but no `<link rel="manifest">` and no SW. Why: a return visit after 5 minutes re-validates 25–40 JSON requests (304s, but one RTT each on mobile); "Add to Home Screen" yields a bookmark; a train ride with no signal yields nothing. Fix: pipeline writes `data/manifest.json` `{path: sha1}` and the app fetches `data/<path>?v=<sha>` with `max-age=31536000, immutable`; Workbox SW: precache shell, stale-while-revalidate for data, offline fallback; `manifest.webmanifest` with icons. **M**.

**W6-9 — Search is three unrelated systems with no Hebrew normalisation and no index.** Evidence: (1) omnibox `Search.tsx:47-70`: linear substring scan with `toLowerCase()` only over registry + groups + 1,251 fund names + `search/rows.json` (625 KB raw / 43 KB br); ranking = `startsWith` + kind bonus; "על ידי" vs "על-ידי" are separate hits (A3-B5 still open); no final-letter folding (ם/מ), no gershayim/geresh folding (״ ׳ "), no prefix handling (ו/ה/ב/ל/מ/ש), no typo tolerance. (2) `DocSearch.tsx:12,37-46`: downloads the full page text of every filing in scope and runs `indexOf` — `search/phoenix_2025FY.json` is 387 KB br for one filing; corpus = 40 filings, 10,364 pages, 34.9 MB raw (`search/index.json` [V]); "all companies, one period" = ~7 × 300 KB per query; caps 2 hits/page, 300 total; no phrase/AND/OR. (3) in-table row filter in `Company.tsx` (`q`). Why: "find a line item by name" scored 2/10 in audit 3; a Koyfin-class omnibox is the primary navigation of a terminal. Fix: pipeline builds one normalised inverted index with a Hebrew normaliser (NFKC, strip niqqud, fold finals, fold quotes/hyphens, generate prefix-stripped variants) in three shards: entities (≈15 KB), statement lines (≈150 KB, lazy), filing text as Pagefind-style per-term chunks (loaded by term hash, ~5–20 KB per query) or a MiniSearch index per filing-year; one query API with field boosts and company grouping. **M**.

**W6-10 — All user state is per-device `localStorage`; two incompatible `useStored` implementations.** Evidence: `lib/local.ts` (prefix `fox:`) used for watchlist, notes (`Follow.tsx:17`), saved views (`Company.tsx:297`), matrix columns, density; `Valuation.tsx:21-24` re-implements `useStored` with keys `fox.dcf.*`/`fox.sotp.v2.*`, no cross-tab event; `RESUME.md:50` lists "sync notes and watchlist across devices" as open. Why: the owner works on phone and desktop; saved views, DCF inputs and notes do not follow; a cleared browser loses everything; the AI layer (W6-19) needs an identity anyway. Fix: Firebase Auth (Google provider, email allowlist in Firestore rules) + one Firestore doc per user per key, wrapped behind the existing `useStored` signature (local-first, write-through, last-write-wins with `updatedAt`); delete the Valuation copy. **M**.

**W6-11 — Chatty first loads: 13 requests for "latest filings" on home, 14 provenance files eagerly on sectors.** Evidence: `Home.tsx:29` `useDocsOf(withDocs)` → 13 × `companies/<id>.docs.json` [V, net log]; `IndustrySectors.tsx:358` fetches every `lts_prov/<c>.json` on mount (182 KB br) although it is read only when a number's source sheet opens. Why: request count dominates on high-RTT mobile; HTTP/2 helps but 40 requests per route is 4× a well-built SPA. Fix: pipeline emits `filings_latest.json` (one request, ≈3 KB); lazy-load `lts_prov/<c>` inside `Source.tsx` on open. **S**.

**W6-12 — `market.json` duplicates `funds.json` and stores 15,823 rows as JSON arrays.** Evidence: key sizes [V]: `rows` 1,397,533 bytes (15,823 × 13 numbers, 176 monthly periods since 2012-01), `funds` 607,195 bytes (1,251 funds) — the same universe as `funds.json` (829,680 raw) which `/funds` loads alongside it. Why: the fund list ships twice on `/funds`; 2012–2019 months are rarely viewed but always downloaded; the `Market` class (`market.ts:30+`) re-aggregates on the client at every view change. Fix: split `market.json` into `market/meta.json`, `market/rows_2020+.json` (default) and `market/rows_2012-2019.json` (lazy), columnar typed arrays (`Int32Array` via base64 or plain column arrays; ~3× smaller before brotli); drop `funds` from it (reference `funds.json`). **S–M**.

**W6-13 — Chart engine: good series model, leaky edges.** Evidence: `foxchart.ts:69,156` read `window.innerWidth` at option-build time — the narrow (phone) layout of `foxPeers` is chosen once and not rebuilt on rotation/resize (the `ResizeObserver` in `Chart.tsx:29` only calls `resize()`); `polish()` (`foxchart.ts:120`) mutates arbitrary option objects typed as `Record<string, unknown>` because pages still hand-roll ECharts options; `cssColor` probes a canvas per token per theme (fine) but `chartBase()` is called per chart build (16 `getComputedStyle` calls per chart). Why: the chart layer is the product's face; rotation bugs and per-page option drift are what audit 3 caught as label overlaps. Fix: pass container width from the observer into `build(width)`; make `FoxSpec`/`PeerSpec` the only public API (lint rule: no `EChartsCoreOption` outside `lib/`); memoise `chartBase()` per theme. **S–M**.

**W6-14 — Duplication across the 27 pages: no shared table, four `fmt`s, 57 hand-written tables.** Evidence: duplicate top-level names across files [V]: `fmt` ×4, `COLS` ×4, `isPct` ×3, `KIND` ×3, `BASIS` ×3, `Delta`/`Notes`/`SECTIONS`/`Src`/`OWN` ×2; `<table` appears 57 times across 27 files (Funds 6, CompanyIfrs 5, Market 4); 64 inline `style={{…}}`; `components/ui.tsx` has `Seg/Field/Kpi/Empty/Loading/ErrorBox` only. Why: sorting, sticky headers, density, keyboard navigation, CSV export and provenance click-through are each implemented 0–1 times per table instead of once; every design-system change (ws4) costs 27 edits. Fix: `components/DataTable.tsx` (columns spec, sort, sticky first column, density from `fin.dense`, CSV/XLSX export hook, `Sourced` cells) and `lib/fmt.ts` as the single formatter; migrate the 6 largest pages first. **M**.

**W6-15 — Type safety stops at the network boundary: no runtime validation of 23 data files.** Evidence: `useData.ts:9-12` `r.json()` cast to `T`; 176 non-null assertions in `web/src`; `foxchart.ts:115` `type Loose = Record<string, unknown>`. Why: a renamed key in `build_workbook.py` fails silently in the browser (blank cells, NaN) rather than in CI. Fix: zod schemas in `packages/core/schemas` for `market/kpi/companies/<id>/ifrs/funds/lts/sop/series`; a Node test validates every built JSON (runs in < 10 s) as a deploy gate; `useLoad` validates in dev only. **S–M**.

**W6-16 — Accessibility has intent but no tooling.** Evidence: 40 `aria-label`, 21 `role`, 10 `aria-pressed`, 1 `aria-modal`; charts are `role="img"` with a label and no table alternative (CSV exists but is a download); 79 `font-size: …px` vs 3 `clamp()`; no skip link; no axe run anywhere. **W6-17 — i18n readiness: Hebrew is in 2,700 string literals.** Evidence: ≈2,731 Hebrew literals in `pages/` + `components/` + `lib/`, 477 of them centralised in `lib/labels.ts` (data labels); `lang="he" dir="rtl"` hard-coded in `index.html`; numbers formatted `en-US` with LRM hacks (`foxchart.ts:57`). ## 3. Radical moves

**RM1 — Target architecture "fox v2" and migration path (preserves every data asset).**
What: a small monorepo — `packages/core` (pure TS: `Market`, `CompanyStore`, `CompanyKpi`, `Lts`, `foxchart` series model, zod schemas, Hebrew normaliser; zero React), `apps/web` (Vite + React, `BrowserRouter`, route-split, service worker, DataTable), `functions/` (gen 2: `chat`, `share-preview`), `pipeline/` unchanged, `web/public/data/` unchanged in shape but content-addressed by a manifest. Migration: (1) week 1 — repo to local SSD + GitHub Actions + Playwright baseline screenshots of the current site (so every later step is diffed against today); (2) week 2 — extract `packages/core` by moving files (no behaviour change), add schemas and the data-contract test; (3) weeks 3–4 — routing, splitting, search index, fonts, headers, SW; (4) weeks 5–8 — auth/sync, export, AI function on top of `core`. Why it beats Koyfin/Fiscal: same URL/sharing/offline ergonomics, with a provenance layer and free data they do not have [J]. Cost: ≈ 6–8 engineer-weeks total. Risk: regression during (3) — mitigated by (1); owner workflow change (Drive → git) — mitigated by keeping Drive for PDFs.

**RM2 — Content-addressed, sharded data layer with offline.** What: pipeline writes `data/manifest.json` + hashed, immutable files; `market.json` split by era and columnar; per-company bundles already exist (`ifrs/<id>/<period>`, `series`, `sop`) — keep; Workbox SW precaches shell + the user's watchlist companies on idle. Why: first route < 300 KB compressed, repeat visits instant and offline, zero 5-minute staleness logic. Beats Koyfin on mobile cold start [J]. Cost: 1–1.5 weeks. Risk: SW cache bugs — ship with a kill-switch header and version banner.

**RM3 — One search platform with a Hebrew-aware index.** What: pipeline-built inverted index (entities → statement lines → filing full text) with the normaliser from W6-9, Pagefind-style chunked loading, one omnibox (`/`, ⌘K) that answers "הראל csm", "רכיב הפסד", "17,717" and "פרמיות ברוטו כלל Q2'26" with grouped, ranked, deep-linked results. Why: full-text search across Hebrew insurer filings with page-level links is something neither Koyfin, Fiscal.ai nor prodata offer [J/T]; it is the fastest path from question to source page. Cost: 1.5–2 weeks. Risk: index size for 10k pages (≈ 3–6 MB total, loaded in 5–20 KB chunks — acceptable).

**RM4 — Identity, sync and "views as links".** What: Firebase Auth (Google) + Firestore behind `useStored`; every page state already in the URL (statements page owns 14 params, `Company.tsx:79`) becomes a saved, named, shareable view with an OG preview card rendered by `functions/share-preview` (title, company, period, one KPI). Why: Koyfin's My Graphs/dashboards sync [V per audit 3] is the feature analysts cite; fox already has the URL-state discipline, it lacks the account. Cost: 1.5 weeks. Risk: Firestore rules — allowlist-only, no public writes.

**RM5 — Export engine from the series model.** What: `FoxSpec`/`PeerSpec` and `DataTable` column specs feed ExcelJS (formatted workbook with a source sheet) and PptxGenJS (native, editable PPT charts in the house palette), lazy-loaded. Why: "a number, a chart, a source" delivered into the owner's own IC memo in two clicks; free competitors give PNG. Cost: 1 week. Risk: Hebrew RTL in PptxGenJS text boxes needs `rtlMode` testing.

**RM6 — Quality system as a product feature.** What: CI gates (typecheck, pipeline checks, schema validation, Playwright visual 390/1440 × phoenix/dark, axe), preview channels per PR, `version.json` in the footer, Sentry + web-vitals. Why: the brand promise "never fabricate numbers" needs a mechanical guarantee between pipeline and screen; today it is a shell script counting files. Cost: 1 week initial. Risk: flaky visual diffs — use per-route masks for charts' anti-aliasing, 0.2 % threshold.
