# אפיון: פלטפורמת נתונים וגרפים לענף הביטוח, הפנסיה והגמל בישראל

> סטטוס: טיוטה v0.1 · 8.10.2026 · לא נבנה קוד. מסמך זה הוא אפיון בלבד.

## 1. שורה תחתונה

- **אפשרי, וכדאי לבנות אתר סטטי מותאם אישית ולא Power BI.** מה שראית בתמונה (טבלת מדדים עם צ'קבוקסים, גרף שמתעדכן, שינוי כולל ו-CAGR, LTM/שנתי/רבעוני, בחירת יחידות) הוא UX של טרמינל נתונים. Power BI עושה את זה גרוע.
- **"לא לייב" זה נכון, ואין בזה פגם.** דוחות מבטחים מתפרסמים רבעונית ונתוני פנסיה/גמל חודשית, עם פיגור של 1–2 חודשים. הדבר היחיד שיכול להיות לייב הוא מחיר מניה. ב-v1 לא נכלול אותו, ובשלב מאוחר יותר נוסיף אותו כרענון סוף יום.
- **הקליטה הידנית-למחצה על ידי (קריאת PDF) עובדת רק עם בקרה.** כל נתון נשמר עם מקור (קובץ + עמוד), עובר בדיקות הצלבה אריתמטיות, ונכנס לאתר רק אחרי אישור.
- **היתרון התחרותי הוא KPI ענפיים.** מהתמונה נראה שגם Fiscal.ai כבר מכסה מבטח ישראלי בשקלים, אבל בטקסונומיה גנרית ("Premiums and Annuity Revenues", "Asset Management Fee"). זו הערכה שלי מתוך צילום המסך ולא אימתתי אותה. בטקסונומיה כזאת סביר שאין CSM, יחס כושר פירעון, זרימות נטו לפנסיה ודמי ניהול לפי מוצר. זה הפער שהמוצר שלך ימלא.

## 3. מה האתר עושה (תכולת מוצר)

### 3.1 מסכים

1. **Company Explorer.** עמוד חברה בסגנון התמונה: טבלת מדדים עם צ'קבוקסים, גרף משותף, עמודות LTM + שנים/רבעונים, בורר יחידות (₪ אלפים/מיליונים/מיליארדים), בורר תדירות (שנתי/רבעוני/LTM), בורר תצוגה לכל סדרה (עמודות/קו/מוערם), "שינוי כולל" ו-CAGR בכותרת הסדרה.
2. **Sector Compare.** אותו מדד לכמה חברות בגרף אחד, כולל נרמול (₪ מוחלט, % מהסכום, אינדקס=100).
3. **Pension & Gemel Module.** גופים ומסלולים: נכסים מנוהלים, תשואה (חודשית, שנתית, 3/5 שנים), דמי ניהול, צבירה נטו (הפקדות פחות משיכות והעברות), נתח שוק. מחולק לפי סוג מוצר: קרן פנסיה חדשה/ותיקה, קופת גמל, קרן השתלמות, גמל להשקעה.
4. **Life Insurance Module.** פרמיות והכנסות, נכסים מנוהלים בפוליסות משתתפות/יחידות, CSM (תנועה: פתיחה → עסק חדש → שחרור → אחר → סגירה), תוצאת שירות ביטוח, תוצאת השקעות, מוצרי צמיחה, יחס כושר פירעון.
5. **Export.** כל תצוגה לאקסל (עם נוסחאות חיות איפה שרלוונטי) ולמצגת PowerPoint. טבלאות עם הערות שוליים, יחידות ומקור, בסגנון בנקי השקעות.

## 4. נתונים

### 4.1 מקורות וסדר עדיפויות

| שכבה | מקור | תדירות | שיטה |
|---|---|---|---|
| דוחות מבטחים | MAYA, אתרי IR (PDF), מצגות משקיעים | רבעוני + שנתי | קריאת PDF על ידי Claude → טבלת staging → בדיקות → אישור |
| פנסיה/גמל/השתלמות | הרשות לשוק ההון (גמל-נט, פנסיה-נט) | חודשי | **אם יש קובץ/API מובנה - הורדה אוטומטית (בלי PDF). זה הנכס הכי שווה בפרויקט.** |
| מחירי מניות | ספק מורשה / TASE | סוף יום | שלב 3 |
| הערכות אנליסטים (forward) | אין מקור חופשי | – | לא ב-v1. לא נמציא. מכפילי forward יחושבו רק אם נקבל קונצנזוס מקור מורשה. |

### 4.2 מודל נתונים (טבלת עובדות ארוכה)

```
entities   (entity_id, name_he, name_en, type[insurer|pension|gemel|fund_house], ticker, parent_id)
metrics    (metric_id, name_he, name_en, unit, category, sign_convention, is_derived, formula)
facts      (entity_id, metric_id, period_end, period_type[Q|H|FY|LTM|M],
            value, currency, scale, basis[reported|restated],
            accounting_regime[IFRS4|IFRS17], consolidated_flag,
            source_doc_id, source_page, extracted_at, status[draft|verified])
sources    (source_doc_id, url, doc_type, published_at, hash)
```

**החלטות חשובות:**

- **שבר סדרה IFRS 17.** סדרות לפני ואחרי המעבר אינן ברות השוואה (דוגמה: הראל 2024, רווח כולל 1.1 מיליארד ש"ח לפי IFRS 4 מול 1.6 מיליארד ש"ח לפי IFRS 17). השדה `accounting_regime` חובה, והגרף מסמן את השבר ולא מחבר את הקו.
- **וינטג'.** כל נתון נשמר כפי שדווח (`reported`) וגם כפי שהוצג מחדש (`restated`). בלי זה ההיסטוריה משתנה בשקט.
- **נגזרים בחישוב, לא ידנית.** LTM = סכום 4 רבעונים. רבעון 4 = שנה פחות 9 חודשים. CAGR/שינוי כולל מחושבים בצד הלקוח.
- **מיפוי תוויות.** שמות סעיפים משתנים בין חברות ושנים. טבלת `label_map` שמצמידה כל תווית מקור ל-`metric_id`. מיפוי חדש דורש אישורך.

### 4.3 צינור קליטה

```
PDF/קובץ → הורדה + hash → חילוץ (Claude) → staging (draft)
        → בדיקות אוטומטיות → דוח חריגים → אישור אנושי → verified → build → אתר
```

בדיקות אוטומטיות חובה:

1. סכום מגזרים = סה"כ מאוחד (בטולרנסיית עיגול).
2. נכסים = התחייבויות + הון.
3. ארבעת הרבעונים = שנה.
4. תנועת CSM: פתיחה + תנועות = סגירה.
5. חריגה חדה מהרבעון הקודם (מעל סף) → דגל לבדיקה.
6. כל נתון עם מקור ועמוד, כדי שתוכל ללחוץ ולראות את הדף.

**הסתייגות כנה:** חילוץ מטבלאות PDF בעברית (RTL, מספרים הפוכים, סימן מינוס בסוגריים, "באלפי ש"ח" לעומת "במיליוני ש"ח") הוא המקום שבו יופיעו שגיאות. הבדיקות לעיל קיימות כדי לתפוס אותן. הן לא מבטיחות אפס שגיאות, והאישור האנושי הוא חלק מהתהליך.

## 5. ארכיטקטורה

**אתר סטטי, בלי שרת.** הנתונים הם קבצי JSON/Parquet שנבנים מראש. אין עלות תחזוקה, ואפשר לאחסן ב-GitHub Pages או Cloudflare Pages.

| רכיב | בחירה | נימוק |
|---|---|---|
| Frontend | React + Vite + TypeScript | סטנדרטי, ניתן לתחזוקה |
| גרפים | Apache ECharts | עמודות/קו/מוערם/שני צירים, RTL, ביצועים |
| טבלאות | TanStack Table | צ'קבוקסים, עמודות דביקות, תצוגה דחוסה |
| שאילתות בדפדפן | DuckDB-WASM (אופציונלי) | SQL על Parquet בלי שרת |
| ייצוא אקסל | ExcelJS / SheetJS | עם עיצוב ויחידות |
| ייצוא PPT | PptxGenJS | גרף + טבלה + הערות שוליים |
| Backend נתונים | DuckDB/SQLite + סקריפטי Python | מקור אמת, בדיקות, build |
| Excel Backend | חוברת master שנוצרת מאותו DB | לשימוש ידני וביקורת |
| i18n | עברית (RTL) + אנגלית | מספרים תמיד LTR |

**מדוע לא Power BI:** מהיר יותר לבנות, אבל אין בו את אינטראקציית הצ'קבוקס→גרף, אין ייצוא PPT/אקסל בסגנון מותאם, והוא מחייב רישוי. אם המטרה היא הדגמה פנימית מהירה, אפשר לשקול אותו כנתיב משני. לא ממליץ עליו כמוצר.

## 7. סיכונים והסתייגויות

1. **פרויקט נתונים, לא פרויקט UI.** עיקר העבודה ועיקר הסיכון נמצאים בניקוי, מיפוי תוויות והשוואתיות בין חברות. את ה-UI אפשר לבנות במהירות.
2. **תלות בשלב 0.** אם הנתונים של הרשות לשוק ההון אינם זמינים בפורמט מובנה, מודול הפנסיה/גמל יהיה יקר פי כמה. עדיין אפשרי, אבל לא בחינם.
3. **IFRS 17 והשוואתיות.** כל חברה מציגה CSM, הוראות מעבר ופילוח מגזרי בצורה שונה במקצת. מדד "אחיד" דורש הגדרה מפורשת והערת שוליים.
4. **פרסום ציבורי.** אם האתר ייפתח לאחרים: לבדוק תנאי שימוש של MAYA ושל מקורות מסחריים, ולהציג רק נתונים שמקורם ציבורי ומצוטט. אל תעתיק עיצוב או נתונים של EY.
5. **אין הערכות אנליסטים בחינם.** אם תרצה השוואת שווי נכונה (forward EPS, forward ROE, P/E עתידי), נצטרך מקור קונצנזוס מורשה. עד אז נציג trailing בלבד ונסמן זאת במפורש.
